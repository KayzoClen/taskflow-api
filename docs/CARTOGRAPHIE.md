### EXO 1 :

```
README.md : présentation et démarrage du projet : Dev : Lecteur : racine du projet
package.json : Métadonnées du projet (description, scripts, dépendances) : Dev : lead tech (pour la validation des versions): racine du projet
commentaire dans le code /src : doc technique en ligne : Dev : Relecteur du code : Dans le code source
commit : description de l'avancement des features : dev : Collaborateurs : dans l'historique de git
Le remote : issues, pr, discussions, wiki : dev : collaborateurs : Sur le remote github/gitlab ...
config.js : comprendre le fonctionnement de l'API: dev : collaborateur dev : routes/config
```

### EXO 2 :

```
1. Présentation claire du projet (titre, pitch et description essentiel)
   -> En 30 secondes de lecture, un inconnu sait ce que fait le projet, à qui il sert et s'il peut l'utiliser en production.

2. Installation reproductible (ligne de commandes à copier coller)
   -> Un inconnu lance le projet en moins de 2 minutes, sans ouvrir le code ni demander d'aide.
   -> Chaque outil à installer est listé avec sa version minimale et la commande pour vérifier sa version.
   -> Toutes les commandes et tous les exemples donnent exactement le résultat écrit.

3. Documentation de l'API (fonctionnalité clés a prendre en main)
   -> Chaque fonctionnalité a un exemple exécutable tel quel, avec la sortie attendue, y compris en cas d'erreur.

4. Structure du projet (architecture du projet -> d'écrire chaque responsabilité des dossiers)
   -> Chaque paramètre de configuration est listé avec sa valeur par défaut, son rôle et l'endroit où le modifier.
   -> N'importe quelle information se trouve en moins de 30 secondes, et tous les liens fonctionnent.

5. Info pratique pour contribuer (comme c'est un début de projet, expliquer comment faire une issue)

6. Limites et bugs connus
   -> Chaque bug connu, limite ou piège est listé avec l'endroit où il se trouve et son effet, et aucun secret n'apparaît.
```
